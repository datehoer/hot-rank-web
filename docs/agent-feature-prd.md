## 1. 背景

HotDay 已经具备多来源热榜聚合、热点正文抓取、AI 今日要闻、RSS 输出等能力，但用户目前仍需逐个榜单和链接浏览，才能完成以下任务：

- 快速了解今天最值得关注的热点；
- 从大量榜单中筛选某个主题；
- 比较同一事件在不同平台的热度和表达差异；
- 阅读多条内容后形成简明结论；
- 围绕同一主题继续追问。

Agent 功能用于把现有数据和模型能力组织成可连续对话的研究流程。首版不做开放式通用聊天，也不允许 Agent 代替用户执行订阅、邮件、发布等外部写操作。

## 2. 产品目标

### 2.1 核心目标

1. 用户通过自然语言，在 30 秒内完成一次热点检索、总结或对比。
2. Agent 的事实性回答尽可能基于当前热榜及其原始链接，并展示可点击引用。
3. 支持连续追问，让用户无需重复描述上下文。
4. 在现有 FastAPI、Redis、PostgreSQL 和 Vue 3 架构内渐进式落地。
5. 对模型调用次数、正文抓取范围、会话时长和并发进行明确限制，控制成本与风险。

### 2.2 成功指标

首版灰度两周后观察：

- Agent 入口点击用户中，对话成功率不低于 85%；
- 有效对话中，至少包含一次追问的比例不低于 25%；
- 带事实性结论的回答，引用覆盖率不低于 90%；
- 首个内容片段 P95 延迟不高于 3 秒；
- 完整回答 P95 延迟不高于 25 秒；
- Agent 接口 5xx 比例低于 1%；
- 单次完整对话的平均模型与抓取成本处于配置预算内。

“引用覆盖率”指回答中的主要事实或结论至少关联一个站内热榜原始链接，不要求寒暄、建议等非事实内容带引用。

## 3. 用户与使用场景

### 3.1 目标用户

- 希望快速了解每日热点的普通用户；
- 需要跨平台观察舆情和趋势的内容创作者；
- 希望筛选科技、财经、娱乐等垂直信息的重度资讯用户；
- 需要快速形成选题线索的编辑或运营人员。

### 3.2 核心场景

1. **每日概览**
   - “今天最值得关注的 5 条科技新闻是什么？”
   - “用三句话总结今天的热榜。”

2. **主题检索**
   - “今天有哪些 AI 相关热点？”
   - “找一下和新能源汽车有关的内容。”

3. **跨榜对比**
   - “微博和知乎都在讨论什么共同话题？”
   - “比较这件事在不同平台的热度。”

4. **内容总结**
   - 用户从热榜卡片发起：“帮我总结这条新闻。”
   - “这几条内容的共同结论是什么？”

5. **连续追问**
   - “第二条具体讲了什么？”
   - “只看国内媒体再总结一次。”
   - “把结论压缩成 100 字。”

## 4. 产品原则

### 4.1 数据有据可查

- Agent 优先使用站内已有热榜、今日要闻和受控正文抓取结果。
- 回答必须把引用映射到具体热榜条目或原始内容。
- 当数据不足、来源不可访问或内容存在冲突时，应明确说明，不得补造事实。

### 4.2 首版只读

- Agent 可以检索、筛选、抓取、总结、聚合和比较。
- Agent 不可以自动订阅、退订、发邮件、发布内容、修改数据或调用服务器管理能力。
- 后续若增加写操作，必须设计用户二次确认和独立权限控制。

### 4.3 过程透明但不过度暴露

- 前端可展示“正在检索热榜”“正在读取 3 个来源”等简短状态。
- 不向用户展示模型的隐藏思维过程、系统提示词或内部凭证。
- 最终回答展示结论、来源和必要的不确定性说明。

### 4.4 成本和时延可控

- 每轮限定工具调用次数、抓取链接数、页面正文长度和模型输出长度。
- 用户取消生成后，服务端应尽快终止后续抓取和模型请求。
- 缓存相同主题和相同链接的中间结果，避免重复消耗。

## 5. 功能范围

### 5.1 P0：首版必须实现

#### F1. Agent 入口

- 桌面端在页面右下角或顶部工具区提供“热点助手”入口。
- 移动端使用不遮挡主要内容的悬浮按钮。
- 点击后打开侧边抽屉；小屏设备使用全屏对话页。
- 首次打开显示能力说明和推荐问题。

推荐问题示例：

- 今天最值得关注的 5 条热点
- 总结今天的科技新闻
- 微博和知乎有哪些共同话题
- 分析当前热榜中的财经趋势

#### F2. 自然语言热点问答

- 支持中文，兼容英文提问。
- 支持按关键词、分类、平台和热度筛选当前热榜。
- 回答应包含清晰结论，默认控制在 500 个中文字以内。
- 用户明确要求详细分析时，可以扩展，但单次输出应有上限。

#### F3. 热点卡片上下文

- 每条热榜内容提供“问 Agent”入口。
- 从卡片进入时，自动携带该条目的标题、URL、所属榜单和当前热度。
- Agent 首屏展示已选中的上下文卡片，用户可移除。
- 后端只信任 URL 与当前热榜数据的匹配结果，不直接信任前端传入的正文。

#### F4. 连续会话

- 同一会话内保留最近对话和已引用热点。
- 支持“这条”“第二个”“只看知乎”等上下文表达。
- 首版匿名会话默认保留 24 小时，过期后自动删除。
- 用户可以新建会话和清空当前会话。

#### F5. 来源引用

- 最终回答以 `[1]`、`[2]` 等标识引用。
- 回答底部展示来源卡片：标题、平台、热度、更新时间和原始链接。
- 点击引用可定位或打开对应来源。
- 同一 URL 在一次回答中只生成一个引用编号。
- 来源正文获取失败时，仍可引用热榜标题，但必须标注“仅依据榜单信息”。

#### F6. 流式响应与状态

- 使用 SSE 向前端流式传输回答。
- 支持以下用户可见状态：
  - 正在检索热榜；
  - 正在读取来源；
  - 正在整理回答；
  - 已完成；
  - 已取消或发生错误。
- 用户可点击“停止生成”。
- 断流后保留已经接收的内容，并提供重试按钮。

#### F7. 反馈

- 每条 Agent 回答提供“有帮助 / 没帮助”。
- “没帮助”可选原因：
  - 内容不准确；
  - 没有回答问题；
  - 引用不相关；
  - 内容过长或过短；
  - 响应太慢。
- 首版反馈写入 Redis 或日志系统，不触发邮件。

#### F8. 限流与使用提示

- 匿名用户按 IP 和会话双重限流。
- 建议初始值：每 IP 每分钟 10 次、每会话每小时 30 次。
- 达到限制时返回明确的可重试时间。
- 首次使用时提示：“回答由 AI 根据站内热榜生成，请以原始来源为准。”

### 5.2 P1：首版后评估

- 按用户偏好生成个性化日报；
- 保存和分享 Agent 对话；
- 生成 Markdown、图片卡片或邮件草稿；
- 热点时间线与热度变化分析；
- 指定多个日期进行历史对比；
- 登录用户的跨设备会话同步；
- 用户确认后的订阅、推送等写操作；
- 定时研究任务和任务完成通知。

### 5.3 明确不做

- 不提供任意互联网搜索和任意 URL 抓取；
- 不让 Agent 直接访问服务器、数据库控制台或 Docker；
- 不做自动发信、自动发布、自动订阅；
- 不承诺新闻真实性判断或投资、医疗、法律决策；
- 不在首版实现多 Agent 协作；
- 不重写现有“今日要闻”功能，首版仅将其作为可复用数据源；
- 不引入账号体系作为首版上线前置条件。

## 6. 用户体验

### 6.1 主流程

1. 用户打开热点助手。
2. 用户输入问题，或从推荐问题、热榜卡片发起。
3. 前端创建或复用匿名会话。
4. 服务端判断意图，并选择是否调用热榜检索、正文读取、今日要闻等工具。
5. 前端展示简短执行状态。
6. Agent 流式返回答案。
7. 答案结束后展示引用、追问建议和反馈按钮。
8. 用户继续追问，或清空会话重新开始。

### 6.2 页面状态

- **初始态**：能力说明、推荐问题、隐私提示。
- **生成态**：用户问题、执行状态、流式正文、停止按钮。
- **完成态**：回答、引用来源、追问建议、反馈入口。
- **无结果态**：明确说明当前热榜中没有足够信息，并建议调整关键词。
- **错误态**：区分限流、模型超时、来源读取失败和服务异常。
- **离线态**：提示网络异常并允许重试，不重复创建用户消息。

### 6.3 回答格式

默认采用以下结构，但不强制每次出现全部章节：

1. 直接回答；
2. 关键发现；
3. 必要的差异或不确定性说明；
4. 来源列表；
5. 2～3 个可继续追问的问题。

## 7. Agent 能力与工具

首版 Agent 使用单一编排器加受控工具集，不采用多 Agent。

### 7.1 `search_rankings`

用途：在当前热榜数据中搜索和筛选。

输入：

```json
{
  "query": "人工智能",
  "platforms": ["知乎", "微博"],
  "limit": 10
}
```

输出包括：

- 热点标题；
- 原始 URL；
- 平台或榜单名称；
- 热度值；
- 数据更新时间；
- 站内唯一引用 ID。

约束：

- `limit` 最大为 20；
- 数据只来自当前 `/rank/hot` 对应的标准化结果；
- 搜索无结果时返回空列表，不自动扩展到互联网。

### 7.2 `get_topic_detail`

用途：读取一个或多个已存在于热榜中的原始链接。

输入：

```json
{
  "topic_ids": ["topic_123"],
  "max_items": 3
}
```

输出包括标题、清洗后的正文摘要、抓取状态和来源信息。

约束：

- 单轮最多读取 5 个链接，默认 3 个；
- URL 必须来自服务端当前热榜或已缓存的今日要闻；
- 禁止访问内网、回环地址、云元数据地址和非 HTTP(S) 协议；
- 限制重定向次数、响应体大小和抓取超时；
- 页面文本按不可信内容处理，不能覆盖系统指令或工具规则。

### 7.3 `get_today_news`

用途：读取现有 AI 今日要闻缓存。

约束：

- 优先读取 Redis 已生成结果；
- Agent 请求不得隐式触发耗时的今日要闻全量生成任务；
- 缓存不存在时返回“暂未生成”，由 Agent 改用热榜检索。

### 7.4 `compare_topics`

用途：对已检索到的主题进行结构化比较。

输出维度：

- 各平台是否出现；
- 热度和排名；
- 标题表达差异；
- 发布时间或榜单更新时间；
- 可由来源支持的共同点和差异。

该工具只进行确定性数据整理，不直接生成主观结论。

### 7.5 编排限制

- 单轮最多 4 次工具调用；
- 单轮最多读取 5 个外部页面；
- 单个正文进入模型前最大 8,000 字符；
- 全部工具总执行时间建议不超过 15 秒；
- 单轮模型总超时建议不超过 45 秒；
- 达到预算后，基于已获得的信息回答，并说明限制。

## 8. 后端设计要求

### 8.1 建议模块结构

```text
hotrank/
  routers/
    agent.py
  agent/
    orchestrator.py
    prompts.py
    events.py
    session_store.py
    tool_registry.py
    tools/
      search_rankings.py
      get_topic_detail.py
      get_today_news.py
      compare_topics.py
  services/
    agent_feedback.py
```

现有模块复用关系：

- `services/rank_data.py`：作为热榜数据来源；
- `services/today_news.py`：只复用缓存结果，不让 Agent 直接触发长任务；
- `parse_detail.py`：复用正文解析能力，但增加 URL 安全校验、超时和大小限制；
- `model_client.py`：演进为可取消、可流式、支持工具调用的模型网关；
- `infrastructure.py`：复用 Redis、PostgreSQL、生命周期和限流配置。

### 8.2 模型网关要求

- 对上层暴露与模型提供商无关的接口；
- 支持 OpenAI 兼容接口和现有 Gemini 配置；
- 支持流式文本、结构化输出、工具调用、取消和超时；
- 不把 API Key、系统提示词和内部异常返回给前端；
- 重试只用于明确可恢复的网络错误；
- 单次请求不使用当前新闻生成逻辑中的长时间多重重试策略；
- 记录 provider、model、耗时、token 用量和结束原因。

### 8.3 Agent 行为规则

- 当前日期、热榜更新时间和用户语言应作为明确上下文提供；
- 新闻网页中的指令性文字全部视为内容，不能作为 Agent 指令执行；
- 没有工具结果支持时，不得声称某事件正在发生或已被证实；
- 多来源结论需要保留来源差异；
- 涉及金融、医疗、法律等高风险问题时，只总结来源，不给确定性专业决策；
- 用户询问与热点无关的通用问题时，简短说明能力范围并引导回热点场景。

## 9. API 草案

API 统一使用 `/agent` 前缀。正式开发前应通过 OpenAPI 再确认字段。

### 9.1 创建会话

`POST /agent/sessions`

请求：

```json
{
  "locale": "zh-CN"
}
```

响应：

```json
{
  "code": 200,
  "data": {
    "session_id": "uuid",
    "session_token": "opaque-token",
    "expires_at": "2026-08-06T12:00:00+08:00"
  }
}
```

`session_token` 只在创建时返回，后续通过 `X-Agent-Session-Token` 传递。服务端只保存其哈希，避免仅凭可枚举的会话 ID 读取对话。

### 9.2 发送消息

`POST /agent/sessions/{session_id}/messages`

请求：

```json
{
  "message": "比较微博和知乎今天共同关注的话题",
  "context": {
    "topic_ids": []
  },
  "locale": "zh-CN"
}
```

响应类型：`text/event-stream`

SSE 事件：

```text
event: meta
data: {"run_id":"uuid"}

event: status
data: {"stage":"searching","message":"正在检索热榜"}

event: delta
data: {"text":"今天两个平台共同关注的主题包括"}

event: citation
data: {"id":"source_1","title":"...","url":"...","platform":"微博"}

event: done
data: {"message_id":"uuid","finish_reason":"stop","usage":{}}
```

错误事件：

```text
event: error
data: {"code":"MODEL_TIMEOUT","message":"生成超时，请重试","retryable":true}
```

### 9.3 获取会话

`GET /agent/sessions/{session_id}`

- 返回仍在 TTL 内的消息、引用和状态；
- 必须校验会话令牌；
- 不返回系统提示词、工具原始凭证或隐藏执行内容。

### 9.4 删除会话

`DELETE /agent/sessions/{session_id}`

- 删除会话消息、引用和相关缓存；
- 返回幂等成功结果。

### 9.5 取消运行

`POST /agent/runs/{run_id}/cancel`

- 标记运行取消；
- 停止尚未开始的工具调用；
- 尽可能取消正在进行的模型或 HTTP 请求。

### 9.6 提交反馈

`POST /agent/messages/{message_id}/feedback`

请求：

```json
{
  "rating": "down",
  "reason": "citation_irrelevant"
}
```

## 10. 数据设计

### 10.1 首版存储策略

首版不新增持久化会话表，匿名会话使用 Redis：

| Key | 内容 | TTL |
| --- | --- | --- |
| `agent:session:{id}` | 会话元数据、令牌哈希、语言 | 24 小时 |
| `agent:messages:{id}` | 最近消息及引用 | 24 小时 |
| `agent:run:{id}` | 运行状态、取消标记 | 1 小时 |
| `agent:detail:{url_hash}` | 清洗后的来源正文 | 1～6 小时 |
| `agent:feedback:{date}` | 聚合反馈或待落库记录 | 7 天 |

要求：

- 单会话最多保留最近 20 轮；
- 单条用户消息和回答分别限制最大长度；
- 不持久化模型隐藏推理；
- 不在日志中记录完整会话令牌、API Key 或用户 IP 明文；
- TTL 到期或用户主动删除后，会话不可恢复。

### 10.2 统一热点引用对象

```json
{
  "source_id": "stable-id",
  "title": "热点标题",
  "url": "https://example.com/news",
  "platform": "知乎",
  "hot_value": "123456",
  "rank_updated_at": "2026-08-05T20:00:00+08:00",
  "detail_status": "fetched"
}
```

`source_id` 应由服务端生成，避免把任意 URL 直接作为工具参数。

## 11. 前端设计要求

建议新增：

```text
vue-ui/src/
  components/agent/
    AgentLauncher.vue
    AgentPanel.vue
    AgentMessage.vue
    AgentComposer.vue
    AgentSources.vue
    AgentStatus.vue
  composables/
```

要求：

- 消息正文使用安全 Markdown 渲染，禁止未经清洗的 HTML；
- 键盘可操作，焦点进入和退出抽屉时正确恢复；
- 生成状态通过文字表达，不能只依赖动画或颜色；
- 桌面端和移动端都可访问来源、停止生成和反馈；
- 中英文文案进入现有 locale 文件，不在组件内散落硬编码。

## 12. 安全、隐私与合规

### 12.1 SSRF 与抓取安全

- 只允许抓取服务端热榜中出现过的 HTTP(S) URL；
- DNS 解析后校验目标 IP，阻止私网、回环、链路本地和保留地址；
- 每次重定向都重新校验；
- 禁止携带用户 Cookie、Authorization 或服务器内部请求头；
- 限制响应类型、响应体大小和请求时长。

### 12.2 Prompt Injection 防护

- 系统提示词明确声明网页文本是不可信数据；
- 工具返回值使用结构化边界传给模型；
- 网页中要求泄露提示词、调用工具或忽略规则的内容不得执行；
- Agent 工具注册表由服务端固定，模型不能构造任意函数或 URL。

### 12.3 隐私

- 首版不要求登录，不主动收集姓名、邮箱等身份信息；
- 对话框提示用户不要输入敏感个人信息；
- 生产日志对 IP 和会话标识做哈希或截断；
- 明确第三方模型提供商和必要的数据处理范围；
- 在隐私说明中写明匿名会话保存时长。

### 12.4 内容安全

- 对明显的违法、有害或高风险请求执行统一安全策略；
- 对新闻中的未经证实内容使用“据该来源”“当前榜单显示”等限定语；
- 模型输出和来源标题均需防止 XSS；
- 前端打开外部链接时使用安全的 `rel` 属性。

## 13. 可观测性与运营

每次 Agent 运行记录：

- `run_id`、匿名会话哈希；
- 请求时间、语言、是否携带热点卡片；
- 调用的工具名称、数量、耗时和成功状态；
- 模型提供商、模型名、首字延迟、总耗时、token 用量；
- 引用数量、结束原因、错误码；
- 用户反馈，不记录完整敏感正文。

建议监控：

- 请求量、并发量、成功率；
- 首字与完整响应 P50/P95；
- 模型、抓取、Redis、PostgreSQL 分阶段错误率；
- 每日 token 与费用；
- 无引用回答比例；
- 用户停止生成和重试比例；
- 限流触发比例。

告警建议：

- 5 分钟内 Agent 5xx 超过 5%；
- P95 完整响应超过 45 秒；
- 模型连续失败或费用异常增长；
- Redis 会话写入失败；
- 抓取工具出现内网访问拦截异常增长。

## 14. 错误码

| 错误码 | 场景 | 用户提示 |
| --- | --- | --- |
| `SESSION_EXPIRED` | 会话已过期 | 会话已过期，请开始新对话 |
| `SESSION_UNAUTHORIZED` | 会话令牌无效 | 当前会话不可访问 |
| `RATE_LIMITED` | 超过调用限制 | 请求过于频繁，请稍后再试 |
| `NO_RELEVANT_DATA` | 当前热榜无相关内容 | 当前热榜中暂未找到相关内容 |
| `SOURCE_FETCH_FAILED` | 来源不可读取 | 部分来源读取失败，回答仅依据可用信息 |
| `MODEL_TIMEOUT` | 模型超时 | 生成超时，请重试 |
| `RUN_CANCELLED` | 用户取消 | 已停止生成 |
| `INTERNAL_ERROR` | 未分类服务异常 | 服务暂时不可用，请稍后再试 |

- 模型错误到业务错误码的映射。

### 15.2 集成测试

- FastAPI 后端；
- Redis；
- PostgreSQL；
- 可控的假模型服务；
- 可控的假新闻页面服务。

- 中英文切换。

## 16. 验收标准

满足以下条件后，P0 可进入灰度：

1. 用户可以创建匿名会话，并在刷新页面后恢复未过期会话。
2. 用户可以输入热点问题并看到流式回答。
3. Agent 可检索当前热榜，并能按关键词和平台过滤。
4. 从热榜卡片发起时，Agent 能正确识别该条内容。
5. 支持至少两轮连续追问，代词和序号引用上下文正确。
6. 有事实性结论的回答展示可点击来源。
7. 任意前端 URL 不能绕过服务端热榜白名单触发抓取。
8. 用户可停止生成，停止后不再产生新的工具调用。
9. 模型超时、抓取失败、限流和会话过期均有明确提示。
10. 匿名会话在 24 小时后自动删除，主动删除立即生效。
11. Agent 不会调用订阅、邮件、部署或数据库写入能力。
12. Docker Compose 集成测试和前端类型检查、构建全部通过。
13. 关键指标、错误和模型费用可在日志或监控中查询。
14. 不影响现有热榜、今日要闻、日历、音乐和 RSS 功能。

## 17. 开发阶段建议

### 阶段一：技术验证

- 定义模型网关接口和 SSE 事件；
- 实现只读 `search_rankings`；
- 使用假模型完成端到端流式链路；
- 验证匿名会话、引用和取消机制。

完成标志：命令行或最小页面可完成“搜索热榜并引用回答”。

### 阶段二：P0 后端

- Agent 编排器和固定工具注册表；
- 正文安全抓取；
- 会话、限流、反馈和可观测性；
- Docker Compose 集成测试。

完成标志：全部 P0 API 和错误场景通过自动化测试。

### 阶段三：P0 前端

- Agent 面板、消息、引用和推荐问题；
- 热榜卡片上下文；
- SSE、停止、重试和会话恢复；
- 响应式布局、国际化和可访问性。

完成标志：桌面端、移动端 E2E 通过。

### 阶段四：灰度和优化

- 小流量开放；
- 根据延迟、引用质量和反馈调整提示词与预算；
- 完成成本上限和告警验证；
- 评估 P1 优先级。

## 18. 上线与回滚

- 使用功能开关控制 Agent 入口和后端路由；
- 首先仅对测试环境和内部 IP 开放；
- 再按流量比例灰度，不直接全量；
- Agent 故障时关闭入口，不影响现有热榜接口；
- 模型提供商异常时返回可重试错误，不降级为无引用的自由回答；
- 回滚不删除仍在 TTL 内的 Redis 会话，除非存在安全风险。
